3. React app requests JWT from Cloud Run server, then loads PDF in iframe

================================================================================
PDF RENDERING MODES
================================================================================

This application uses THREE different rendering strategies depending on the
device type and server configuration:

MODE A: NATIVE BROWSER PDF VIEWER (Default for Desktop/Android)
  - Platforms: Desktop browsers (Chrome, Firefox, Edge, Safari) and Android
  - Method: PDF displayed using browser's native PDF viewer in <iframe>
  - Benefits: Fast loading, native zoom/scroll controls, minimal JS overhead
  - Quality: Native PDF rendering quality
  - Activation: Automatic for non-iOS devices

MODE B: PDF.js CANVAS RENDERER (Default for iOS)
  - Platforms: iOS devices (iPad, iPhone) when SERVE_PNGS_FOR_IOS=false (default)
  - Method: PDF rendered to <canvas> elements using Mozilla's PDF.js library
  - Why: iOS Safari has limitations embedding PDFs in iframes
  - Benefits: Works on iOS, page preloading, fully scrollable
  - Quality: PDF.js applies some compression; good but not lossless
  - Activation: Automatic for iOS devices when PNG mode is disabled

MODE C: HIGH-RESOLUTION PNG IMAGES (Optional for iOS)
  - Platforms: iOS devices (iPad, iPhone) when SERVE_PNGS_FOR_IOS=true
  - Method: Server sends PNG file array, client renders as scrollable column
  - Why: Provides superior image quality vs. PDF.js compression
  - Benefits: Lossless quality, smooth scrolling, lazy loading
  - Drawbacks: Larger file sizes, increased bandwidth usage
  - Activation: Requires PNG files + SERVE_PNGS_FOR_IOS=true env var

HOW MODE SELECTION WORKS:
  1. Client detects device type (iOS vs. other)
  2. Client sends device info + PDF filename to server during auth
  3. Server checks SERVE_PNGS_FOR_IOS flag and scans for PNG files
  4. Server responds with rendering instructions (usePngMode + pngFiles array)
  5. Client renders using the specified mode

TO ENABLE PNG MODE FOR iOS:
  1. Set SERVE_PNGS_FOR_IOS=true in Cloud Run environment variables
  2. Export PDF pages as PNG files: [basename]-1.png, [basename]-2.png, etc.
  3. Place PNGs in PDFPasswordServer/pngs/ directory
  4. Deploy to Cloud Run (PNGs are automatically included)

DEPLOYMENT CONFIGURATIONS
================================================================================

This file supports multiple deployment configurations. Each configuration is
a separate deployment (e.g., proposal, cover letter/CV, etc.).

To add a new deployment:
1. Copy an existing configuration section (e.g., "=== ExampleProject ===")
2. Rename it (e.g., "=== MyNewProject ===")
3. Update all values within that section
4. Use the config name when running deployment scripts

⚠️ IMPORTANT DISTINCTION:
   - The Cloud Run URL contains a number that is NOT the Project ID
   - Always use GCP Project ID for gcloud commands
   - These numbers are different and serve different purposes

7. Staging Subdirectory (nested under Production):

    your-service-name

    false
    ⚠️ When true: iOS devices get high-res PNG images instead of PDF.js
    ⚠️ When false: iOS devices use PDF.js renderer (default)

12. PNG Naming Scheme (informational):
    [PDF-basename]-[pageNumber].png
    ⚠️ This is AUTOMATIC - you don't configure it, just follow this format
    ⚠️ Example: If PDF is "your-document.pdf", name PNGs as:
       your-document-1.png, your-document-2.png, your-document-3.png, etc.
    ⚠️ Place all PNG files in PDFPasswordServer/pngs/ directory
    ⚠️ Page numbers should start at 1 and be sequential (no gaps)

NOTE: When staging, the full path will be: [Production Subdirectory]/[Staging Subdirectory]/
      Example: https://yourdomain.com/your-subdirectory/stage/

================================================================================
PREREQUISITES FOR DEPLOYMENT
================================================================================

Before deploying, ensure the following are set up:

1. Docker Desktop is installed and running
2. Google Cloud CLI (gcloud) is installed
3. Authenticated with GCP: gcloud auth login
4. Correct GCP project is active: gcloud config set project [GCP Project ID]
5. Required GCP APIs are enabled (Cloud Run, Cloud Build, Artifact Registry)

Note: If APIs aren't enabled, the deployment command will prompt you to enable them.

================================================================================
USING THE DEPLOYMENT SCRIPTS
================================================================================

The deployment scripts automatically read values from production-config.txt
and update your code files before building/deploying.

UPDATE SERVER CODE:
  node scripts/updateServerFromConfig.js update [ConfigName]
  node scripts/updateServerFromConfig.js revert

UPDATE CLIENT CODE:
  node scripts/updateClientFromConfig.js update [ConfigName]
  node scripts/updateClientFromConfig.js update [ConfigName] --staging
  node scripts/updateClientFromConfig.js revert

If production-config.txt is missing, the scripts will provide instructions
on how to set it up using this template file.
